## 1. 연구 전제

- MI-CDM이 ETL되어 있는 상태를 전제로 함.
- 코호트는 ATLAS를 활용해 정의하며, index date와 observation window 등을 설정함.

## 2. 연구 파이프라인

파이프라인은 규리T 버전으로 고정하며, 다음 6단계로 구성함.

### 1) Retrieve

MI-CDM에서 실제 DICOM 파일을 가져오는 모듈.

Retrieve 시작점:

- `person_id`
- `image_occurrence_id`
- `local_path`

### 2) Profile

- 가져온 데이터를 전처리 전에 연구자가 확인할 수 있도록 제공.
- 연구 초기 단계에서 데이터 특성을 파악할 수 있어야 함.
- **민성:** Fingerprint 버전을 기반으로 검토.

### 3) Preprocess

전처리 방식은 추가 검토가 필요함. 다음 두 방식 중 어떤 것을 사용할지 비교·검토해야 함.

- MI-CDM ETL validation에서 사용한 전처리 방식
- pydicom 기반 전처리 방식

### 4) Models

- 모델 실행 과정에서 사용자 자유도를 어느 수준까지 허용할지 결정해야 함.
- **민성:** TaskSpec 버전을 기반으로 검토.
- Hyperparameter 등의 설정 방식 정의.
- Task 및 모델 정보 관리
  - RSNA
  - ATLAS `model.json`
  - `.pth`
  - GitHub
  - Hugging Face

### 5) Evaluation

평가 과정을 체계화하며, 평가지표는 다음 세 범주로 구분하는 방향을 검토함.

- Discrimination
- Calibration
- Interpretation

### 6) Misclassification

모델의 오분류 사례와 오류 분석 결과를 자동으로 확인할 수 있도록 구성함.

## 3. Technical Report

Retrieve부터 misclassification까지의 전체 과정과 결과가 하나의 Technical Report 형태로 정리되어 연구자에게 제공되면 좋겠음.

## 4. ATLAS와 Multimodal Framework의 차이

**ATLAS**

- 보수적인 연구자가 사용하는 비교적 안정적인 환경.
- 요구사항과 구조가 크게 변하지 않을 가능성이 높음.

**Multimodal**

- 기술과 요구사항이 지속적으로 변화할 가능성이 높음.
- 요구되는 specification의 범위도 매우 넓음.

### Channel Definition Sequence

- 총 12개의 sequence가 존재함.
- `image_value_order`를 구분하는 key로 사용함.
- DICOM 파일마다 channel의 순서가 다를 수 있음.
  - 따라서 DICOM 파일 내부에 기록된 순서대로 `value_order`에 저장됨.
- `value_order`가 없는 값은 개별 channel이 아닌 전체 ECG에 대한 값임.

각 Sequence별로 분리되는 값:

- `SamplingFrequency`
- `ChannelLabel`
- `ChannelSensitivity`
- `ChannelSensitivityUnitsSequence`
- `ChannelBaseline`
